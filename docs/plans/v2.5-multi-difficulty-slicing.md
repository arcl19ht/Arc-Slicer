# V2.5 多难度切片

## 背景与用户价值

Arc Slicer 旧版正式导出固定处理歌曲目录中的 `2.aff`；V2.5-A 已完成目录驱动的多难度纯逻辑基础，V2.5-B 已将其接入正式写盘。多难度切片在不破坏既有单难度导出、音频复用和外部目标壳安全边界的前提下，让一个片段目录包含用户选择的多个难度 AFF。

本计划是现行开发规划，不替代历史需求书。已确认的标准图表映射为：`0.aff`/Past/PST/ratingClass 0、`1.aff`/Present/PRS/ratingClass 1、`2.aff`/Future/FTR/ratingClass 2、`3.aff`/Beyond/BYD/ratingClass 3、`4.aff`/Eternal/ETR/ratingClass 4。

## 当前事实与不变原则

- 正式写盘输入为用户选择的可用标准难度；旧 slides 缺少新字段时仍优先恢复 `2.aff` 以保持兼容。
- 可用难度只由目录实际存在的普通可读 `0.aff`–`4.aff` 得出。任意子集均合法，不要求 0/1/2，同时存在 3/4 也合法。
- 既有片段 ID 保持不变：`<source_song_id>_<start_ms>_<end_ms>_x<speed_token>`。
- 一个片段输出目录可以包含多个难度 AFF。
- 对同一片段和倍速，`base.ogg` 必须只切一次，不得因难度重复运行 ffmpeg。
- 不改变 AFF 切片语义、`current_export` / `library_export` 结构或 external merge 的安全边界。

## V2.5-A2：专属音源与单条 songlist 聚合基础

- `N.aff` 与可用 `N.ogg` 同时存在时，N 具有目录派生的 `audioOverride: true`。`audioOverride` 不持久化为用户输入，也不生成显式 `false`。
- `N.ogg` 存在而 `N.aff` 不存在时为 orphan override audio：报告 warning，不映射为可用难度，也不进入导出计划。
- 已选难度的 `N.ogg` 存在但不可用时，计划明确失败，不能静默回退 `base.ogg`。
- 音频操作不变量为“每个片段、每个不同源音频一条操作”：始终有 `base.ogg`，每个已选可用 `N.ogg` 各一条；未选和 orphan 音源不参与。
- 一个片段只有一个 song ID 和一个 songlist song 条目，所有真实难度聚合在同一个按 ratingClass 排序的 `difficulties` 数组中。
- ratingClass 0/1/2 始终保留壳兼容条目：真实选中难度使用实际元数据，其余使用 `rating = -1` 占位；3/4 只在实际选中时出现。
- 每难度元数据已具备纯逻辑模型；旧 FTR 字段迁移到 ratingClass 2。可选 title override 与 audioOverride 独立，空白或同标题时省略 `title_localized`。本阶段不推导 `jacketOverride`。

## V2.5-A：多难度基础与兼容模型

本阶段已实现但不接线：`arc_slicer.difficulties` 中的单一定义、AFF/专属音源资产发现、选择验证、slides 解析/序列化辅助和每难度元数据模型，以及多 AFF/OGG 导出计划和单条 songlist 聚合计划。它不调用 ffmpeg、不读取真实用户歌曲、不写输出目录，也不修改 current/library export 或 external merge。

1. 已定义 `0.aff`–`4.aff` 的稳定文件名、名称、缩写和 ratingClass 映射。
2. 已定义歌曲级 `available_difficulties` 与 `selected_difficulties`：前者只来自扫描，后者去重、排序、验证且可报告缺失文件。
3. 已定义 slides 持久化字段 `selected_difficulties`：新导入默认所有可用；旧 slides 缺字段时优先 `[2]`，否则所有可用；显式空值和缺失文件均保留错误状态。
4. 已建立多难度 `songlist.difficulties` 的迁移设计：旧 FTR 的 0/1/2 为壳兼容占位，不能误认为实际 chart availability 或 selected outputs。
5. 外部测试壳和 Windows 源码验收已由 V2.5-C 覆盖；Windows EXE、真实游戏目录和其他文件系统仍未验收。不得假定难度只支持 0–3。

## V2.5-B：选择、持久化与多 AFF 导出

实现状态：已完成自动化实现和 Windows 源码人工验收。主界面以 `arc_slicer.difficulties` 的 discovery 作为唯一来源，显示真实标准 AFF、未知 AFF 和孤立 override warning；选择持久化为歌曲级 `difficulty_settings_by_song`，旧 FTR metadata 迁移到 ratingClass 2。正式 `do_slice()` 逐片段执行一次 base audio、每个选中有效 override audio 和每个选中 chart，随后写入一条聚合 songlist entry。试听下拉是运行时状态，切换时重载现有播放器和 waveform，不持久化也不改变 canonical duration。current/library export 仍按完整 song ID 目录替换，external merge 未改安全模型。

在 V2.5-A 审计结论确认后实施：

- 难度选择 UI 与持久化。
- 每难度元数据和 title override UI、专属音源状态和试听音源选择。
- 选中 AFF 的发现、校验、切片和写入同一片段目录。
- 多难度 AFF/OGG 正式切片和单条 songlist 聚合写盘，并接线 current/library export 与 external merge。

## V2.5-B 边界校验补充

`base.ogg` 保持 canonical 片段校验来源；当前试听源另行探测时长，越界时不会设置播放区间或修改片段。正式导出在创建 staging 前只探测实际使用的唯一音源（base 和已选有效 `N.ogg`），任一不可探测或片段终点越界都会阻止写盘。该补充已通过自动化、Windows 源码检查和合成来源的真实写盘验收；Windows EXE 仍待验收。

## V2.5-B 生命周期与试听补充

Waveform worker 的 `done_signal` 只表示生成结果已可处理，不表示 `QThread` 已结束；active worker 引用必须保留到 `finished`，窗口关闭时请求中断并等待所有 worker 自然结束。合法但没有谱面事件的 AFF 仍是有效输入，例如 `AudioOffset:-30` 后接 `-`。手动 Space 和播放按钮在选中片段、试听音源、区间及有效倍速未变化时暂停和原位恢复；只有试听 spec 改变时才重置区间。以上已通过自动化和 Windows 源码人工验收；Windows EXE 仍待验收。

## 数据与兼容约束

- 难度发现结果应区分已知、未知、缺失和不可读文件，不能静默丢弃用户选择。
- slides 新字段必须有明确版本兼容与迁移规则，旧保存数据不能因升级失效。
- `speed_override`、片段区间、`uid`、`link_group_id` 与多难度选择保持正交。
- 同一片段内每个难度共享同一时间边界和切后音频，但各自保留自己的 AFF 内容。

## 外部合并边界

V2.5 不放宽 external merge 的目录验证、计划、确认、备份、manifest 或失败恢复规则。多难度输出只改变合法 staging 歌曲目录中的内容，不得改变外部合并的安全模型。
